# git 워크플로 규칙

**적용 시점**: 항상. 커밋·브랜치·푸시·PR 관련 작업.

## 브랜치
- 기본 브랜치는 `main`. 대회 기간(~10/13)에는 각 작업자가 작업 단위마다 커밋하고 `main`에 바로 푸시해 계속 합친다. 기능 브랜치는 선택.
- 푸시 전 `git pull --rebase`로 다른 작업자 커밋을 먼저 받는다. 충돌은 직접 풀고, 남의 변경을 지우는 쪽으로 풀지 않는다.
- 브랜치를 쓸 때 이름: `feat/<주제>`, `fix/<주제>`, `docs/<주제>`.
- `main`에 강제 푸시하지 않는다.

## 커밋
- 대회 기간에는 Claude가 작업 단위(기능 하나, 문서 갱신 하나)가 끝날 때마다 커밋하고 `main`에 푸시한다. 요청을 기다리지 않는다.
- 커밋 전에 `.env`가 스테이징되지 않았는지, 비밀 값이 diff에 없는지 확인한다.
- 테스트가 깨진 상태로는 푸시하지 않는다.
- 커밋 메시지는 한글. 접두어는 `feat:` `fix:` `docs:` `refactor:` `test:` `chore:`.
- 문서만 바뀌면 `docs:`.
- `.env` 등 비밀 파일은 절대 커밋하지 않는다.
