# 데이터베이스 규칙

**적용 시점**: 테이블·컬럼·인덱스·접근 정책을 추가·변경·삭제하거나, DB 타입 정의를 고칠 때.

## 금지 / 허용
- 스키마 변경은 `/db-change-plan` 승인 후에만 한다. 승인 없이 마이그레이션 파일을 만들지 않는다.
- 기존 마이그레이션 파일은 수정하지 않는다. 되돌리려면 새 마이그레이션을 만든다.
- 컬럼 삭제·타입 변경처럼 데이터가 사라질 수 있는 변경은 백업 절차를 계획에 포함한다.
- 새 마이그레이션은 `.claude/skills/deploy/migrations.md` 대기 목록에 추가한다.
- 스키마 상세는 `.claude/skills/db-schema/` 를 정본으로 하고, 변경 시 같이 갱신한다.

## 이유
- 스키마는 되돌리기 어렵고 코드 전반에 영향을 준다.
