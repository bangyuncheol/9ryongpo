# 권한 규칙

**적용 시점**: 로그인·세션·역할·리소스 접근 제어와 관련된 코드를 만들거나 고칠 때.

## 금지 / 허용
- 권한 검사는 항상 서버에서 한다. 클라이언트 상태(UI 숨김 등)는 편의일 뿐 보안 경계가 아니다.
- 리소스에 접근하는 모든 서버 진입점(API, 서버 액션)은 누가 요청했는지 먼저 확인한다.
- 역할·권한 목록을 새로 만들면 `db-schema` 와 `requirements` 스킬에 같이 기록한다.
- 관리자 전용 기능에는 반드시 관리자 확인 로직을 둔다. 숨겨진 URL 로 대신하지 않는다.

## 이 프로젝트 (2026-10-09)
- 로그인 없음. 화면·조회 API·구독은 공개.
- 시뮬레이터 시계 조작(`/api/sim/*`)·데이터 소스 전환·시험 알림(`/api/push/test`)도 토큰 없이 연다(10/10 오너 결정: 우리만 쓰는 데모 도구). 공개 주소를 아는 사람은 조작할 수 있다는 점을 알고 쓴다.

## 이유
- 권한 누락은 데이터 유출로 직결된다.
