# UI 디자인 규칙

**적용 시점**: `src/web/` 아래 화면·컴포넌트·스타일·문구를 만들거나 고칠 때.

## 기준 디자인 언어 — 삼성 One UI (2026-10-09 결정)
- 데모 기기가 갤럭시이고 사용자가 갤럭시 크롬으로 연다. 그래서 시각·행동 언어는 One UI를 따른다.
- 참고 문서: `.claude/rules/samsung-one-ui.md` (공개 자료 기반 비공식 카탈로그, 출처 번호 포함). 이 파일은 그 문서에서 **이 제품에 쓸 것만** 골라 정한다. 충돌하면 이 파일이 우선이다.
- **적용 시점**: 지금 화면은 뼈대다. One UI 반영은 UI 작업 단계(방윤철 님 담당)에서 한 번에 한다. 그 전까지 새 컴포넌트도 아래 원칙을 어기지 않게만 만든다.

## 금지 / 허용
- 기존 컴포넌트가 있으면 재사용한다(`src/web/src/components/`). 비슷한 컴포넌트를 새로 만들지 않는다.
- 색·간격·라운드·글꼴은 `src/web/src/index.css`의 `@theme` 토큰으로만 쓴다. 컴포넌트에 hex·px 값을 하드코딩하지 않는다.
- 모든 인터랙티브 요소는 키보드로 조작 가능하고, 이미지·아이콘에는 대체 텍스트를 둔다.
- 사용자 문구는 한국어. 오류 문구는 `.claude/rules/error-handling.md`를 따른다.

## One UI에서 가져오는 원칙 (출처는 samsung-one-ui.md)
- **보는 영역 위, 누르는 영역 아래**: 상단은 시각·요약(비인터랙티브), 버튼·입력은 아래쪽. 가장 중요한 행동(알림 받기, 질문 입력)은 화면 하단 엄지 닿는 곳.
- **결정은 아래에서**: 확인·선택 다이얼로그는 하단 시트, 정보 안내만 중앙. 팝업은 입력·삭제 확인·동의·중대 정보로 한정.
- **버튼 체계 하나**: 한 화면에 flat 또는 contained 한 가지만. 강조는 배경색(회색=중간, 유채색=높음)으로만 올린다.
- **좌우 여백 최소 24px, 인접 터치 대상 간격 8px 이상**.
- **모션 100~500ms**, 기본 곡선 `cubic-bezier(0.22, 0.25, 0, 1)`.
- **대비**: 작은 글자 4.5:1, 큰 글자 3:1 이상. 글자 200% 확대에도 깨지지 않게. 색만으로 상태를 전달하지 않는다(입항 중/입항/대기는 색 + 글자·모양).
- **문구**: 목적 없는 텍스트는 싣지 않는다. 막다른 안내 대신 할 수 있는 행동을 준다. 사용자를 탓하지 않는다.
- **다크 모드**: UI 작업 단계에서 라이트·다크 토큰을 함께 정의하고 둘 다 확인한다.

## 이 제품의 결정 (One UI에 발행값이 없어 제품이 정한 것)
- 터치 대상 최소 크기 44px — One UI는 크기 수치를 발행하지 않았다(samsung-one-ui.md Known Gaps). 제품 결정으로 표기한다.
- 한글 글꼴은 Pretendard 우선. One UI 폰트 스케일 9단(40/20/19/18/17/16/15/14/13px)은 Roboto 기준이라 크기 참고로만 쓴다.
- line-height·굵기 숫자·그림자 수치는 One UI 발행값이 없다. 정할 때는 "제품 결정"으로 `index.css`에 주석을 단다.

## 하지 않는 것
- 발행되지 않은 수치를 One UI 값이라고 부르지 않는다.
- "One UI", "Samsung", "Galaxy" 이름이나 `sec_*`·`one_ui_*` 같은 이름을 화면 문구·클래스·파일명에 넣지 않는다.
- 갤럭시 시스템 화면(설정·퀵패널 등)의 맥락을 그대로 옮기지 않는다. 가져오는 것은 시각·행동 언어뿐이다.
- Material 기본 컴포넌트를 그대로 두고 One UI 스타일이라 부르지 않는다.

## 디자인 기준 (현재 토큰)
- 정본은 `src/web/src/index.css`의 `@theme`. 지금 값은 뼈대용 임시 값(바다색 계열)이며 UI 작업 단계에서 One UI role 구조(primary / primary-dark / control-activated)에 맞춰 다시 정한다.
