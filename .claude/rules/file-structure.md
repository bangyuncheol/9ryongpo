# 파일 구조 규칙

**적용 시점**: 항상. 특히 새 파일을 만들거나 파일을 옮길 때.

## 배치 원칙
- 루트 폴더는 세 종류만: 문서·자산은 `NN_한글/`(01_설계·02_수신자료·03_발표·04_영상·05_브랜드, 번호순), 코드는 `src/`, 데이터는 `data/`. 새 최상위 폴더가 필요하면 다음 번호를 붙인다. (2026-10-15)
- 소스 코드는 `src/` 아래: `server/`(FastAPI) · `web/`(Vite+React) · `android/`(TWA) · `deploy/`(VM 스크립트). 서비스 코드만 둔다.
- 무언가를 생성하는 스크립트는 산출물 옆에 둔다(`03_발표/make_pptx.py`, `04_영상/final/build.py`, `01_설계/make_architecture_svg.py`).
- 문서는 4계층을 따른다: 절대 규칙은 `CLAUDE.md`, 작업 규칙은 `.claude/rules/`, 스펙·이력은 `.claude/skills/`, 반복 절차는 `.claude/commands/`.
- 루트에는 설정 파일과 "루트 참고 문서"(`CLAUDE.md` 문서 구조 절에 등재된 것)만 둔다. 임시 파일·실험 코드를 루트에 남기지 않는다.
- 같은 규칙을 두 문서에 적지 않는다. 정본 하나를 정하고 나머지는 `→ .claude/rules/xxx.md` 포인터로 쓴다.

## 이유
- 규칙과 스펙이 섞이면 무엇이 현행인지 판단할 수 없게 된다.
