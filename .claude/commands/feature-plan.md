다음 요청에 대한 구현 계획을 작성하고, 코드는 아직 수정하지 말고 승인을 기다린다. 요청: $ARGUMENTS

## 출력 형식
1. 목표 — 한 문장
2. 영향 범위 — 수정·추가할 파일 목록
3. 데이터 변경 — 스키마 변경이 있으면 `/db-change-plan` 필요 여부 명시
4. 구현 순서 — 단계별로
5. 테스트 — 추가·수정할 테스트와 수동 확인 항목
6. 위험 요소 — 되돌리기 어려운 것, 다른 기능에 미치는 영향
7. 문서 갱신 — 바뀌어야 할 rules·skills·CLAUDE.md 항목

작성 시 준수사항:
- 관련 `.claude/rules/` 와 `requirements` 스킬을 먼저 읽는다.
- `CLAUDE.md` "의도적으로 하지 않는 것"과 충돌하는지 확인한다.
- 승인 전에는 파일을 만들거나 고치지 않는다.
