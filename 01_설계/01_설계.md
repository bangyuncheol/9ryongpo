## 0. 30초 요약

**사용자** — 구룡포 위판장에 생선을 사러 오는 사람. 데모 페르소나는 **횟집 사장**(경매에 직접 참여하는 중도매인·식당). 관광객·일반 소비자도 같은 화면을 그대로 본다(모드 구분 없음, §1-16).

**문제** — 새벽 경매에 무엇이 얼마나 언제 들어오는지, 배가 닿기 전엔 아무도 모른다. 헛걸음하거나 트럭에 막힌다.

**에이전트가 하는 일** — 밤새 지도를 보고 아침을 준비해 두는 당직자.
① 입항 예보 → ② 어종·물량 추정 → ③ 구독 알림(웹 푸시) → ④ 위판장 앞 교통 현황(실시간) → ⑤ 질문창(tool calling)

**데이터** — E-UM 어선 명부·위판장 좌표·교통 센서(살아 있음) + E-UM 선박 위치(멈춤 → 시뮬레이터) + 해양수산부 일자별 위탁판매현황(어종·시세, 월간).

**스택** — FastAPI + Vite/React SPA + SQLite, 대회 제공 GCP VM 한 대. 알림은 웹 푸시(갤럭시 크롬). 문자 발송 없음.

**데모** — 시뮬레이터로 새벽 3~6시를 재생하며 지도 위에서 배가 들어오고 폰에 알림이 온다. 설정 하나로 실제 API로 전환해 보인다.

### 2.1 페르소나

**주 사용자: 횟집 사장 김○○(구룡포 읍내).** 매일 새벽 위판장 경매에서 사 온다. 지금은 새벽 4시에 나가 보거나 아는 선장에게 전화한다. 알고 싶은 것: "오늘 붉은대게 들어오나, 몇 척이나, 몇 시 경매에 맞추면 되나, 트럭 몰리기 전에 빠질 수 있나."

LLM은 도구 결과의 숫자를 그대로 인용만 한다. 계산은 전부 도구 안. 시스템 프롬프트에 "숫자를 만들어 내지 말 것, 근거 월을 함께 말할 것"을 명시.

**답하는 범위(10/10 결정).** 입항 배·어종·물량, 위판·경매 시각과 과거 실적, 위판장 앞 교통, 알림 신청, 사용법, 인사만 답한다. 그 밖(계산·코딩·번역·일반 상식·다른 지역·역할극·규칙 무시 요구)은 정해진 한 문장으로 거절한다. 세 겹으로 막는다.
1. 범위 판정 호출: 질문(과 이전 질문)만 보고 IN/OUT 한 단어(`reasoning low`). 본 답변과 **동시에** 시작해 지연을 늘리지 않고, OUT이면 본 호출을 끊고 거절 문장을 낸다. 범위 안 내용이 섞여 있으면 IN. 판정 호출이 실패하면 막지 않는다.
2. 본 답변 시스템 프롬프트에도 같은 범위 규칙. 섞인 질문은 범위 안 부분만 답하고 범위 밖 부분은 언급하지 않는다(10/10).
3. 화면이 보낸 이전 대화는 assistant 발화가 아니라 "참고용 기록" 한 덩어리로 넣는다(가짜 이전 답을 끼워 넣는 탈옥 차단).

### 4.3 전화 알림 (10/11 오너 승인, `app/phone/`)

채팅이 익숙지 않은 사용자를 위해 입항 알림을 070 전화로도 건다. 받으면 AI가 알림을 읽고 질문을 받는다. 답은 질문창과 **같은 엔진**(범위 판정 + 도구 6개 + 규칙)이 내고, 전화 말투 규칙(`chat.VOICE`)만 덧붙인다.

| 맡는 쪽 | 하는 일 |
|---|---|
| ClawOps | 070 번호, 발신·벨·연결, 전화 음성(μ-law 8kHz) ↔ PCM 변환, 우리 서버와 연결 유지(공개 주소 불필요), 부품 사이 전달, 말 끊기(AI 음성 멈춤), 통화 종료 |
| 우리 `stt.py` | 같은 음성을 두 곳에 동시에. **CLOVA Speech**(gRPC): 확정 문장, 키워드 부스팅(오늘 배 이름·어종), semanticEpd 0.8초 침묵마다 문장 확정. **OpenAI 받아쓰기 전용 연결**: 모델 기반 말 시작 감지(말 끊기·말하는 중 대기)와 CLOVA 실패 시 대비책. 확정 문장은 흔한 오류를 바로잡아 넘긴다('멋있고'→'뭐 싣고', '댁에'→'대게', '지33'→'제33') |
| 우리 `brain.py` | 첫마디 = 인사 + 알림 문장 + "더 궁금하신 거 있으세요?"(걸려 온 전화는 인사 + 소개 + "궁금하신 거 있으세요?"). 질문은 물어보기 엔진으로. 쿠션 "네, 확인해 볼게요."를 바로 먼저(10/11 실통화: 말 끝→쿠션 약 3초 → SDK 대기 0.5→0.1초, 우리 대기 0.6초 제거로 약 1.1초 단축). "없어요" 같은 끝맺음이면 끝인사 후 끊음 |
| 우리 `tts.py` | Gemini TTS. 문장별 음성을 `data/tts_cache/`에 저장해 재사용(하루 100회 한도), 고정 문장 7개는 기동 때 한 번만 생성. 실패 시 그 문장만 OpenAI `gpt-4o-mini-tts` |
| 우리 `service.py` | 발신 조건·허용 번호·동시 통화 1건 대기열·화면용 통화 기록·끝인사 뒤 끊기·말 없음 25초/최대 150초 자동 종료 |

- interview_bridge에서 가져온 것은 엔진이 아니라 설계다: 고정 쿠션 음성을 미리 만들어 바로 재생, 침묵 길이로 말 끝 판정(면접 2.4초 → 전화 0.8초), 합성 음성 문장별 캐시. 엔진 자체는 브라우저 전송·재생 큐·말 끊기가 ClawOps와 겹치고, 0.1초 틱 상태 기계라 파이프라인 구조에 맞지 않으며, 도구 호출이 없어 쓰지 않는다.
- 안전장치: `PHONE_ENABLED=1`인 서버만 번호에 붙는다(번호당 연결 하나라 로컬·VM이 동시에 붙으면 서로 밀어냄). `CALL_ALLOWED_NUMBERS`에 있는 번호만 저장·발신(문자 인증은 "문자 발송 안 함" 결정과 겹쳐 쓰지 않음). 입항 알림 발신은 진행 막대 '전화 켜기'가 켜졌을 때만(기본 꺼짐, 체험 발신 10분 보호).
- 비용(실측·업체 표기): Gemini TTS 말한 시간 1분당 약 1.4~1.7센트, 받아쓰기 1분당 약 0.3센트. Realtime 음성 모델은 통화 전체 음성 입력이 과금돼 쓰지 않는다(10/11 오너 결정).
- **전화 범위 밖 처리(10/11).** 전화 범위 판정은 IN/OUT에 UNCLEAR(받아쓰기가 틀린 듯 뜻이 안 통하는 문장)를 더한다(`chat.GATE_VOICE`, 화면 채팅은 그대로). 받아쓰기 최저 글자 확신도(logprobs, 지연 증가 없음 — 켬·끔 모두 말 끝→확정 0.57초)와 함께:

  | 판정 | 확신도 | 응답 |
  |---|---|---|
  | IN | 무관 | 그대로 답(배 이름 같은 고유명사는 맞아도 확신도가 낮을 수 있어 막지 않는다) |
  | OUT | 0.2 미만 | "죄송해요, 제가 잘 못 들었어요. 한 번만 다시 말씀해 주세요." |
  | OUT | 0.2 이상 | "그건 제가 안내해 드리기 어려워요. 들어오는 배나 어종, 위판장 앞 교통을 물어봐 주세요." |
  | UNCLEAR | 무관 | 다시 묻기 |

  두 번 연속 못 알아들으면 "들어오는 배, 대게, 위판장 앞 교통 중에 어떤 게 궁금하세요?"로 바꿔 같은 말을 반복하지 않는다. 기준값 0.2는 합성 음성 시험(틀린 문장 0.00~0.05, 맞은 문장 0.32~0.97)에서 정했고 실통화 로그(`받아쓰기 확정 … 최저 확신도`)로 다시 맞춘다. 상위 모델 `gpt-4o-transcribe`는 같은 시험에서 낫지 않아 쓰지 않는다.
- **받아쓰기 CLOVA 전환(10/11 오너 승인).** 실통화 녹음 6개 비교: 배 이름 '남진호' CLOVA(키워드 부스팅) 5/5, OpenAI 1/5. OpenAI에 배 이름 힌트를 넣으면 4/5지만 알아듣기 어려운 음성에서 힌트 전체를 받아쓰기로 내뱉어(녹음 04) 쓸 수 없다. CLOVA도 '대게→댁에', '뭐 싣고→멋있고'를 틀려 바로잡기 규칙을 둔다. 비용: 월 60분 무료 뒤 1분 600원(interview_bridge와 무료 시간 공유), OpenAI 연결은 1분 약 4원.
- **말 중간에 쉬는 경우(10/11 실통화).** 0.8초 넘게 쉬면 받아쓰기가 문장을 둘로 나눠 앞 절반에 먼저 답했다. 받아쓰기 연결의 말 시작·말 끝 신호로 '말하는 중'을 기억해, 쿠션과 답을 내보내기 전에 그 말의 받아쓰기가 확정되기를 최대 3초 기다린다(말 끝 신호가 아니라 확정에서 풀어, 말 끝→확정 사이 약 0.6초에 쿠션이 먼저 나갔다 끊기는 일을 막음. 소음으로 확정이 안 오면 그대로 답). 그사이 뒷말이 확정되면 파이프라인이 앞 응답을 취소하고, 답하기 부품이 이어진 사용자 말을 한 질문으로 합친다. 끝인사 뒤 끊기 전 여유는 2초(0.8초는 말 끝나자마자 끊기는 느낌).
- **통화 상한(10/11).** 걸려 온 전화 300초(수신 무료), 우리가 거는 알림 전화 150초(발신 시간 보호). 상한이 지나면 하던 답 뒤에 "통화가 길어져 이만 끊을게요. 다시 걸어 주시면 이어서 알려 드릴게요."를 말하고 끊는다. 40초를 더 넘기면 그냥 끊는다(150초에 답 도중 끊긴 실통화 반영).
- 첫 실통화(10/11, 수신 105초): 질문 4개 모두 끝까지 처리, "감사합니다"에 끝인사 후 정상 종료. 답은 받아쓰기 확정 뒤 5.6~7.9초(범위 판정+도구). 첫 질문이 "오늘 돈 돼 있나요?"로 잘못 받아 적혀 거절 문장이 나감 → 아래 재질문 규칙으로 고침.
- 실측(10/11): Gemini 첫 소리 1.22초(9.2초 분량을 3.5초에 합성, 스트리밍), 받아쓰기는 말 끝 후 약 1초에 확정, 힌트 단어로 '자망선' 정확 인식.

## 5. 기능 상세

### 5.1 입항 판정 (`rules/arrival.py`) — 초기값, 시뮬레이터로 보정

입력: `ships_pos` 최신 두 스냅샷. 기준점: 위판장 P(35.9895, 129.5558).

한 배가 **입항 중**이려면 모두 만족:
1. 거리 d(P) ≤ 15 km
2. 속도 ≥ 2 kn
3. 침로와 P 방위각의 차 ≤ 35°
4. 직전 스냅샷보다 d가 줄었다 (스냅샷이 하나면 1~3만)

ETA = 현재 시각 + d / 속도. 항 입구 0.5km 안이면 "입항".
출력: `[ {ship_id, name, biz(어업종류), gt, d_km, speed, eta, confidence} ]`, confidence는 조건 4 충족 시 "높음".

표본 사실: 10/8 응답 50척은 전부 동쪽 6.0~10.5km, 5~10kn 33척. 이 범위가 시뮬레이터 출발 분포.

### 5.2 어종·물량 추정 (`rules/species.py`)

- 어업종류 복원: `sign` 문자열에서 정규식 `([가-힣]+어업)\((\d+)톤\)` → 업종. 괄호 없는 경우(대형정치망 등)는 사전 매핑.
- 같은 달 `auction_stats[월][업종]`의 4개년(2022~2025) 연도별 비중 평균 → 어종 비율. 없으면 인접 월, 해마다 1위가 바뀌는 업종이면 "범주만".
- 물량 지표: 입항 척수 × 톤수 가중을 **상대 등급**(평소보다 적음/비슷/많음)으로만. 절대 kg는 말하지 않는다.
- 가격은 내지 않는다(§1-8).
- 출력 예: "자망 3척(합 22t) → 붉은대게 위주(78%)·골뱅이 조금 (최근 4년 10월 구룡포 실적 기준)".

### 5.3 구독 알림 (`push/webpush.py`)

- 화면 [알림 받기] → 서비스 워커 등록 → `PushSubscription`을 `/subscribe`로 저장 (+ 조건: 어종/업종/전체).
- 트리거: 03:10 정기 브리핑, 그리고 10분 예보 갱신에서 **조건에 맞는 배가 새로 "입항 중"으로 바뀔 때**.
- 본문은 `rules/brief.py`가 LLM으로 한 문장 생성. 실패 시 템플릿 폴백.
- VAPID 키 쌍은 환경 변수. 갤럭시 크롬은 설치 없이 수신. 데모 폰은 크롬 배터리 최적화 해제.

### 5.4 위판장 앞 교통 현황 (`rules/visit.py`) — 실시간, 저장 없음

- 과거 교통량을 쌓아 예측하지 않는다. 화면을 열 때·질문할 때 E-UM을 바로 부르고 5분만 메모리에 둔다.
- 입력: 경매 시각(기본 09:00, 잡어·문어 07:00), 센서3(위판장 80m) 최근 9시간 트럭·전체, 혼잡율 최근 24시간.
- 출력:
  - **지금**: "위판장 앞 지난 1시간 트럭 ○대·전체 ○대".
  - **어제 같은 시각 대비**: 혼잡율 24시간 곡선에서 같은 시각 값과 비교해 "어제 이맘때보다 붐빔/비슷/한산".
  - **하루 중 위치**: 혼잡율 응답이 23시간만 올 때가 있어 어제 같은 시각이 빠질 수 있다(10/9 확인). 그래서 "최근 24시간 중 붐비는 편/보통/한산한 편"을 항상 함께 계산하고, 어제 값이 없으면 이것을 쓴다.
  - **권장 문구**: 경매 시각과 지금 상황으로만 만든다. 예) "경매 09:00. 지금 위판장 앞은 한산합니다. 경매 30분 전 도착 권장". 미래 혼잡 시각을 단정하지 않는다.
- 관광객용 별도 문구는 두지 않는다. 관광객도 경매를 구경하러 올 수 있고, 경매 종료 시각·경매 뒤 혼잡은 확인되지 않았다(10/10). 질문창은 관광객에게 지금 교통과 경매 시작 시각만 알린다.
- 데모 시각(오후)과 시뮬레이터 시계(새벽)가 다르므로, 시연 중 교통 카드는 **실제 현재 시각의 실측**임을 화면에 표기한다.

### 5.5 시뮬레이터 + 라이브 스위치 (`feed/`)

- `FEED=live`: 10분마다 `S03_007` 호출 → `ships_pos` 적재. 수신 시각이 24h 이상 오래되면 화면 배지에 "미갱신(마지막 2025-04-27)" 표시.
- `FEED=sim`: 실제 명부에서 업종 분포(10월 실적 비율)에 맞춰 N척 선택, 실제 50척 좌표를 출발점으로, 03:00~06:00 사이에 5~9kn로 항구 입구 → 수로(3kn) → 위판장 앞 정박 자리로 이동(§1-24). 도착 시각은 흩뿌림. 같은 스키마를 `ships_pos`에 적재.
- `feed/clock.py`: 가상 시계. `/sim/play?speed=60`, `/sim/pause`, `/sim/seek?t=03:30`. 리허설·발표에서 같은 장면 반복.
- 가짜는 "배의 움직임"뿐. 명부·좌표·교통·실적은 실데이터. 발표에서 명시(§9).

## 8. 기술 스택·배포

| 층 | 선택 | 이유 |
|---|---|---|
| 서버 | Python 3.12, FastAPI, APScheduler, httpx, pywebpush, openai | 수집·룰·에이전트·푸시가 한 프로세스 |
| DB | SQLite (VM 디스크의 파일 1개) | 3일. 동시 사용자 수십 명 수준. 재배포에도 남음 |
| 화면 | Vite + React + Tailwind, 카카오맵 JS SDK(실패 시 Leaflet), PWA(manifest + service worker) | 지도·차트·푸시 라이브러리가 가장 풍부 |
| LLM | OpenAI(대회 지원 20만원). 질문창 tool calling, 브리핑 문장 | 투기 호출 없음 → 비용 통제 쉬움 |
| 배포 | 대회 제공 GCP VM 1대, SSH 접속(운영진에 공개키 전달). FastAPI가 `dist/` 정적 서빙. HTTPS는 80·443 포트가 열리면 무료 IP 도메인(sslip.io 등) + 자동 인증서 리버스 프록시, 안 열리면 Cloudflare 터널 | URL 하나. 웹 푸시는 HTTPS 필수 |

환경 변수(이름만, 값은 `.env`. 예시는 저장소 `.env.example`. VM에는 `.env`를 직접 올린다): `EUM_SERVICE_KEY`, `DATA_GO_KR_KEY`, `OPENAI_API_KEY`, `OPENAI_MODEL`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, `FEED`(live|sim), `DB_PATH`.

**코드 위치** — 이 저장소(`9ryongpo`) `src/`. 서버는 `src/server/`, 화면은 `src/web/`. CLAUDE.md 기술 스택 항목이 위 표와 같다.

## 11. 리스크·한계 (발표에서도 밝힐 것)

| 리스크 | 대응 |
|---|---|
| VM에 HTTPS가 없으면 웹 푸시 불가 | 10/10 첫 배포 때 HTTPS 주소부터 확보. 포트가 막혀 있으면 Cloudflare 터널 |
| 선박 위치 미갱신 | 시뮬레이터 + 스위치. 발표에서 명시. 주최 측 질의는 보류 |
| 예상 질문 "선박 데이터가 안 들어오는데 어떻게 만들었나" | 답: "실시간 위치가 들어온다고 가정하고 만들었다. API 응답과 같은 형식의 시뮬레이터로 재생했고, 스위치 하나로 실제 API로 바뀐다(시연 7번). 명부·위판장·교통·위판 실적은 실데이터." 발표 첫 장면(§9-1)에서 먼저 밝혀 질문 전에 해소 |
| 어업종류 ≠ 어종 | 같은 달 실적 분포로 확률 표기. "확실"이라 말하지 않음 |
| 10월 데이터가 2025년 것 | 10/15 9월분 등록 전까지 작년 10월. 화면에 근거 월 표기 |
| 교통량 API 9시간·혼잡율 24시간 | 쌓지 않고 실시간만 쓴다. 미래 혼잡을 예측한다고 말하지 않는다. API 실패 시 "교통 정보를 지금 불러올 수 없습니다" 표시 |
| 푸시 지연(배터리 최적화) | 데모 폰 설정 해제, 리허설에서 지연 측정, 실패 시 화면 내 알림함 폴백 |
| "오늘 얼마냐"는 질문 | 예측 불가를 밝히고 과거 실적만 답한다: "작년 10월 구룡포 경매에서 붉은대게는 kg당 5,800원 안팎(도매가). 오늘 가격은 알 수 없다" |
| OpenAI 20만원 | 투기 호출 없음. 질문당 도구 2~3회, 리허설 포함 1만원 미만 예상 |
| 경매 시각·참여 자격 가정 | "09:00 경매(잡어·문어 07:00), 중도매인 입찰"은 공개 정보 기준 가정. 수협 확인 전까지 화면에 '기본값' 표기 |
